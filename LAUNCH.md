# Release and discovery plan

## Before upload

- Run package checks and behavioral trials. Publish measured results only after running them.
- Add a short demo using a simulated or authorized draft, showing evidence, prose, and publish settings. Do not expose account details or private analytics.
- Include one example with clearly labeled synthetic data, or obtain permission to include real evidence. Do not label synthetic data a successful campaign.

## Distribution

Check the [skills.sh listing](https://skills.sh/vivekkartha/medium-seo-publisher) after each release. Publish a concise release note explaining the specific problem, installation, dependencies, and known limits.

Prepare posts for relevant Medium/agent-skill communities that allow project sharing. Send only when explicitly authorized. Avoid mass outreach, fake engagement, reciprocal star schemes, and claims of guaranteed growth.

Make contribution paths concrete: a reproducible failing case, supported browser evidence, clearer voice preservation, or an improved provider adapter. Respond to issues with tested fixes.

## Measurement

Track repository visitors and clones where available, installs where reported, stars, issues, and successful repeat use. Record windows and unavailable data. Stars are a downstream signal, not a controllable deliverable.

Choose future improvements from user failures and repeat usage. Do not claim speed gains from reduced checklist length or accuracy from popularity.
